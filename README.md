# Orderlens

Приложение проверяет таблицу заказов из CSV или Excel и рассчитывает оплаты, возвраты, средний оплаченный чек, повторные покупки и динамику.

## Статус и границы

Публичное статическое демо: [открыть Orderlens](https://skrlv.github.io/orderlens-analytics-demo/). Отдельный репозиторий: [skrlv/orderlens-analytics-demo](https://github.com/skrlv/orderlens-analytics-demo). Версия приложения 1.0.0, договор данных v1.

Таблица обрабатывается только в памяти текущей вкладки. Приложение не отправляет клиентские таблицы на внешний сервер, не сохраняет их в `localStorage` и не имеет общей базы данных. Перезагрузка удаляет принятый набор и возвращает вымышленный контрольный пример. Для загрузки самой страницы и демонстрационного файла нужен доступ к сайту. Серверной обработки заказов, платежей, CRM и курсов валют нет.

Все заказы встроенного примера вымышлены. Приложение показывает денежные события по договору данных v1, а не бухгалтерскую прибыль или финансовый учёт по отгрузкам.

## Что можно сделать

- Загрузить CSV в UTF-8 с необязательным BOM или книгу XLSX; для CSV выбрать разделитель и десятичный знак, для XLSX — лист, для обоих форматов — строку заголовков.
- Просмотреть первые пять записей, явно выбрать смысл строки и сопоставить колонки.
- Проверить обязательные поля, точные дубли, конфликтующие ключи, части событий и полную историю возвратов. Диагностика указывает лист, запись/строку, поле и причину.
- Принять полный корректный набор. Ошибка отклоняет весь новый импорт и сохраняет ранее принятые данные; частичных отчётов нет.
- Выбрать включительный период и одну валюту, посмотреть показатели, динамику по активным дням или месяцам и принятые события всей истории.
- Скачать отчёт CSV или JSON. JSON дополнительно содержит все нормализованные события для проверки. Экспорт XLSX не реализован.

Полные определения и ограничения находятся в [DATA-CONTRACT.md](DATA-CONTRACT.md).

## Локальный запуск

Нужен Node.js 22 или новее. Браузер должен поддерживать JavaScript-модули, `BigInt`, `Array.prototype.toSorted`, File API и Blob Downloads; подойдут актуальные Chrome, Edge, Firefox и Safari. Точная совместимость со старыми браузерами не заявляется.

Из каталога проекта:

```sh
npm ci
npm test
npm run build
npm start
```

Локальный адрес: http://127.0.0.1:4188/. `npm start` раздаёт готовую папку `dist/`, поэтому после изменения исходников сначала повторите сборку. Другой локальный порт задаётся переменной `PORT`. Остановка — Ctrl+C в терминале сервера.

Для браузерной проверки после установки зависимостей:

```sh
npx playwright install chromium
npm run test:browser
```

Перед этой командой приложение должно быть собрано и доступно локально через `npm start`. Сценарий проверки использует Chromium и сохраняет результаты согласно `tests/browser.mjs`. Команды выше описывают воспроизведение; они не заменяют итоговый протокол фактически выполненных проверок.

## Контрольный сценарий

1. Откройте приложение. Встроенный пример содержит 15 вымышленных строк в режиме **часть события**. После удаления одного точного дубля и объединения S1 получается 13 событий.
2. Выберите RUB и период 01.01–28.02.2026. Ожидаются оплаты 3200.00, возвраты 1700.00, разница 1500.00, 7 оплаченных заказов, средний оплаченный чек 457.14 и повторные клиенты 1 из 3 (33.33%).
3. Выберите 01–28.02.2026. Ожидается разница −500.00 RUB: в феврале есть возврат январского заказа. Средний оплаченный чек остаётся 250.00, поскольку равен оплатам 1000.00 / 4 заказа.
4. Выберите USD за февраль: оплата 50.00, возвраты 0.00, один заказ. USD не прибавляется к RUB.
5. Скачайте [CSV](public/samples/orders-parts.csv) и [XLSX](public/samples/orders-parts.xlsx), по очереди загрузите каждый через импорт. Укажите режим **часть события**, одноимённые колонки и десятичную точку. Для XLSX выберите лист `Заказы`, строку заголовков 1. Результаты должны совпасть с пунктом 2.
6. Загрузите [файл с ошибками](public/samples/orders-errors.csv), задайте тот же режим и подтвердите проверку. Должна появиться диагностика; текущие принятые данные и отчёт сохраняются.
7. Вернитесь к нужному периоду и скачайте CSV и JSON. Сверьте период, валюту, основные показатели, динамику, правила и диагностику с экраном. Формат отчёта CSV отличается от формата исходного файла и не предназначен для повторного импорта как таблица заказов.

Русский вариант [orders-parts-ru.csv](public/samples/orders-parts-ru.csv) требует разделителя `;` и десятичной запятой. Происхождение примера, намеренные ошибки и четыре ручных контроля описаны в [samples/README.md](public/samples/README.md) и [manual-expected.json](public/samples/manual-expected.json).

## Устройство проекта

| Файл или каталог | Назначение |
|---|---|
| `index.html`, `src/style.css` | Русский адаптивный интерфейс, правила и сопоставление колонок |
| `src/app.mjs` | Управление импортом, фильтрами, экраном и скачиванием |
| `src/import.mjs` | Чтение CSV/XLSX, листов, дат Excel и сопоставленных ячеек |
| `src/engine.mjs` | Точная нормализация денег, проверка истории и расчёты |
| `src/export.mjs` | Отчёты CSV и JSON, определения показателей |
| `public/samples/` | Вымышленные тестовые файлы и ручные ожидаемые результаты |
| `public/vendor/` | Локальная библиотека чтения XLSX и её лицензия |
| `scripts/` | Статическая сборка и локальная раздача без API |
| `tests/` | Проверки ядра, импорта/экспорта и браузерного сценария |
| `.github/workflows/pages.yml` | Официальный процесс GitHub Actions для GitHub Pages |

Сборка копирует `index.html`, `src/` и содержимое `public/` в `dist/`. Настройки доступа и секретные ключи не нужны. Отдельной серверной части нет: локальная раздача файлов не выполняет бизнес-расчёты.

## Публикация

Целевой отдельный репозиторий: `skrlv/orderlens-analytics-demo`, ветка `main`, базовый путь сайта `/orderlens-analytics-demo/`. Все внутренние ссылки на ресурсы относительные и совместимы с этим путём. Артефакт публикации — `dist/`.

Workflow использует `actions/configure-pages`, `actions/upload-pages-artifact` и `actions/deploy-pages`. В настройках Pages нужен источник **GitHub Actions** (`build_type=workflow`). GitHub Pages раздаёт статические файлы и не исполняет Node.js-сервер. Публикация считается проверенной после успешного workflow и проверки основного сценария на точном публичном адресе.

## Источники и лицензии

Данные примера подготовлены вручную для этой демонстрации по контрольному набору задачи №18; реальные продажи или результаты клиента не используются. Фотографий и внешних изображений нет. Знак и графики заданы векторно, интерфейс использует системные шрифты без внешней загрузки. Локально поставляемый SheetJS CE для чтения XLSX распространяется по Apache License 2.0; текст лицензии находится рядом с библиотекой в `public/vendor/`. Библиотека не загружается с CDN при работе приложения.
